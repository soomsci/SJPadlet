# 게시판 UI/UX 개선 대장

2026-10-12. 사용자가 Safari에 열어 둔 Padlet 모둠형 게시판의 화면·접근성 트리·섹션 작업 메뉴를 관찰했다. 학교의 실제 학생 이름·게시물·첨부·보드 주소는 이 문서와 테스트에 복사하지 않는다. 아래는 확인한 화면 구조를 본 서비스에 적용하는 요구사항이며 Padlet 전체 기능 실사를 뜻하지 않는다.

사용자 요청: 화면 형식과 사용 흐름을 최대한 비슷하게 구성하고, 위쪽 정보 칸을 줄인다. 모아의 자체 로고·코드·배경을 사용한다. 무료 운영 한도와 기존 서버 권한은 유지한다.

|ID|관찰한 구조·개선 목적|모아 요구와 수용 기준|상태|
|---|---|---|---|
|UX-01|넓은 보드 배경과 작은 상단 정보|큰 정보 패널을 제거하고 제목·두 줄 이내 설명·상태를 표시. 검색·공유·설정을 상단에 배치. 공통 헤더 높이 60px. 작은 화면에서 도구가 겹치지 않음|이번 구현|
|UX-02|모둠별 독립된 열|열 바탕을 투명하게 하고 섹션 제목·작성 버튼·카드를 별개로 배치. 열이 많으면 가로 스크롤. 모바일 열 너비는 화면의 85% 이하|이번 구현|
|UX-03|섹션 제목 아래의 작성 버튼|항상 해당 섹션이 선택된 작성 창을 열며, 긴 열의 맨 아래까지 스크롤하지 않아도 작성 시작 가능|이번 구현·UI 테스트|
|UX-04|섹션 작업 메뉴|제목 변경·왼쪽/오른쪽 이동·섹션 QR을 더보기 메뉴에 모음. 제목 클릭으로도 이름 변경. 입력·배경 갱신 중 초점/커서 보존. 한글 조합 중 Escape로 닫히지 않음|이번 구현·UI 테스트|
|UX-05|카드 안의 반응과 댓글|본문 15px·제목 20px, 작성자·시각·반응 수·댓글 입력을 카드에서 확인. 댓글 허용 또는 기존 댓글이 있으면 기본 펼침. 서버가 허용한 댓글만 표시|이번 구현·UI 테스트|
|UX-06|오른쪽 아래의 게시 버튼|PC·모바일 모두 고정 작성 버튼 표시. 닫힌 활동·읽기 전용·개별 글 초대에서 기존 can_write 조건 준수|이번 구현·기존 권한 검사 유지|
|UX-07|작성 창의 최소화·초안|작성 중 다른 글을 읽고 돌아올 수 있음. 새로고침 복원, 폐기 확인, 기기 공용 사용 시 정리 정책 필요|후속 P0: 저장·소유권 계약부터 설계|
|UX-08|모둠 단위 발표·슬라이드쇼|게시판 전체/현재 섹션 발표, 이전·다음·전체화면·키보드 이동. 대상 밖 글과 대기 글을 로드하지 않음|후속 P1|

|UX-12|작성 미디어 도구|무료 버전에서는 이미지 첨부·참고 링크를 명확히 제공. 녹화·파일 업로드·AI 등 미지원 기능을 동작하는 버튼으로 노출하지 않음|기존 무료 정책 유지; 확장은 P1/P3|

## 검증과 다음 순서

1. 섹션 이름 변경·섹션별 작성·초점·한글 입력 회귀 테스트를 먼저 통과시킨다.
2. 합성 데이터로 Safari 실제 화면을 확인한다. 이것은 원격 DB·학생 수업 검증과 구분한다.
3. `npm run check` 후 기존 Worker에 배포하고, 실제 운영 화면을 새로고침해 변경을 확인한다.
4. Android/iOS, 프로젝터, 키보드, 긴 제목·설명·모둠 6개 이상을 확인한다. 아직 확인하지 않은 환경은 완료로 기록하지 않는다.
5. UX-07을 먼저 설계한 뒤 UX-08~11을 각각 계약·권한·테스트가 있는 작업으로 진행한다. 문서에 추가된 후속 항목은 이번 구현 완료에 포함하지 않는다.
