## 설계 구체화

- Worker는 요청별 환경값과 `pg.Client`를 사용하며 Supabase DB에 Hyperdrive로 접속한다. 권한 조회가 오래된 결과를 반환하지 않도록 쿼리 캐시를 비활성화한다. Node 개발 모드에는 PGlite를 유지한다.
- `supabase/migrations/202610120001_free_hosting.sql`과 체크섬·트랜잭션 기반 적용 스크립트를 추가했다. 앱 테이블은 RLS와 권한 회수로 브라우저 역할의 직접 읽기·쓰기를 막는다. 운영 요청에서 DDL을 자동 실행하지 않는다.
- Google OIDC와 HttpOnly 서버 세션을 유지한다. Supabase Auth로의 사용자 이전은 하지 않았다. 학교 교사 도메인·Workspace hd·명단, 학생 초대와 익명 소유권 검사를 공통으로 사용한다.
- 무료 배포의 이미지는 비공개 Supabase Storage에 저장하고 권한 API로만 다운로드한다. 브라우저 재인코딩·1MB 업로드 제한과 게시판 100MB·교사 200MB·학교 800MB 잠금 기반 한도를 적용한다. 이미지 형식 검증은 백신 검사 완료를 뜻하지 않는다. Node 일반 파일 모드는 ClamAV를 유지한다.
- Realtime에는 빈 무효화 알림만 전달한다. 현재 게시판 접근이 있는 세션에 해당 채널 전용 ES256 JWT를 60초간 발급하고 45초마다 갱신·재조회한다. 앱 데이터·파일 직접 접근 권한은 주지 않는다.
- 회수된 Realtime 연결은 최대 60초간 빈 알림을 더 받을 수 있다. 글·파일·새 토큰 API는 현재 권한으로 즉시 거부한다. 이미 내려받은 내용은 회수할 수 없다. Node SSE는 1초 재검사를 유지한다.
- QR 링크 원문·코드는 생성 응답에서만 전달한다. 기존 초대는 목록·회수 가능하며 다시 표시하려면 새 초대를 만든다.
- 파일 자동 정리·자동 백업 예약·실제 복원·CPU/전송량 실측은 운영 후속 작업이다. 무료 한도를 모두 앱에서 강제하는 구현은 아니다.

## 검증 기록

최초 통합에서 테스트 60개와 Next.js 빌드가 통과했다. 무료 배포 전환 후 웹/Worker 타입 검사 오류 0, 린트 경고/오류 0, 자동 테스트 **71개 통과**(기존 60 + 무료 호스팅 8 + Supabase 정책 3), Vite 정적 빌드와 Worker dry-run이 통과했다. 기존 Next.js 프로덕션 빌드도 별도로 통과했다. npm 의존성 감사 결과 취약점 0개.

생성한 Worker 번들을 실제 workerd 엔진에서 실행하는 `cf:smoke`도 통과했다. 상태 API·정적 파일 라우팅·설정과 무관한 무료 업로드 제한·보안 헤더·교차 출처 차단을 검사한다. 소켓이나 실제 원격 자격 증명을 사용하지 않는다. placeholder 상태의 `deploy:free`는 원격 변경 전에 중단됨을 확인했다.

추가 테스트는 이미지 제한·비공개 Storage 프록시·권한 회수 후 다운로드 거부·동시 학교 용량 한도·Storage 실패 롤백·128KB JSON 한도·단기 채널 토큰·요청별 환경/DB 격리를 검증한다. 실제 생성한 SQL을 PGlite에 적용해 브라우저 역할의 앱 테이블 접근 거부, 비공개 버킷, 빈 알림과 채널 RLS를 검사한다. Supabase 제공 스키마/함수와 Storage HTTP는 테스트 대역이므로 실제 공급자 통합 검증은 남아 있다.

통합 API 테스트에서 교사 게시판 생성→참여 개방→익명 입장→비공개 파일 업로드→승인 대기→교사 승인→댓글·좋아요→차단/해제→닫기→공유 회수→파일 접근 거부를 검증한다. 별도 테스트로 40세션의 동시 글 저장, 열린 SSE 연결의 권한 회수, DB 백업 복원을 확인한다. 이는 단일 개발 DB에서의 API 검증이며 학교망의 응답시간 목표나 전체 500세션 목표 달성을 의미하지 않는다.

브라우저·휴대전화·학교 Google 실제 계정·원격 Supabase DB/Storage/Realtime·학교망·파일 포함 운영 복원은 아직 검증하지 못했다. 로컬 서버 포트가 차단되어 브라우저 검증을 수행하지 못했다. 최초 Cloudflare 연결 실패 후 재개 시 **공식 스킬 설치와 MCP 인증을 확인**했다. 계정·Worker/Hyperdrive 목록 조회 및 `samjeong-moa.workers.dev` 계정 주소 등록을 완료했다. 실제 앱 Worker는 아직 배포하지 않았다. 첫 관리자/허용 교사는 `xopowok08@samjeong.ms.kr`로 설정했다. 구독/결제 조회는 인증 오류로 거부됐으며 플랜 변경·유료 리소스 생성은 하지 않았다. Wrangler CLI는 별도 인증이 필요하다. Supabase 연결 정보와 Google OAuth 클라이언트는 아직 코드에 연결되지 않았다. `.env.free` 비공개 입력 템플릿과 Google OAuth 설정 순서를 준비했다.

## Supabase 연결과 초기 DB 적용

2026-10-12 재개 후 플러그인 관리 화면에는 계정 연결이 표시됐으나 첫 API 호출은 인증 오류를 반환했다. 이후 재조회가 성공했으므로 설치/연결을 다시 요구하지 않는다. `SJPadlet` 조직(`butrqvcqkaspjlzmgrgi`)의 Free 플랜과 서울 리전 프로젝트 `oxaggbmvughcdxsuhlpd`를 확인했다.

기존 public 테이블·Storage 버킷·앱 마이그레이션이 없는 것을 확인하고 MCP로 초기 SQL을 적용했다. 앱 테이블 19개 모두 RLS 활성, anon/authenticated 직접 테이블 권한 0, 비공개 `classroom-images` 버킷의 1MB 및 JPG/PNG/WebP 제한, Realtime 수신 정책과 outbox 트리거를 원격 쿼리로 확인했다. CLI 마이그레이션 스크립트와 중복 적용을 방지하기 위한 `moa_migrations` 체크섬 기록도 추가했다.

Supabase 보안 advisor에는 오류/경고가 없었으며, 앱 테이블의 정책 미설정 INFO는 직접 접근을 의도적으로 차단하는 설계에 따른다. [RLS 정책 없는 테이블 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

프로젝트 URL/publishable key는 Worker 설정과 Git 제외 `.env.free`에 저장했다. Google ID/secret 입력 존재와 ID 형식은 확인했으나 실제 로그인은 미검증이다. 사용자가 DB 주소/비밀번호와 서버용 Supabase secret을 입력했고, 대상 프로젝트 주소·예시 비밀번호 교체·서버 키 형식을 확인했다. 이 실행 환경에서는 DB/Storage 연결 테스트가 DNS `ENOTFOUND`로 중단돼 실제 자격 증명 유효성을 검증했다고 간주하지 않는다. 서명 키 가져오기·활성화, Hyperdrive와 원격 Worker 배포는 아직 남아 있다. 로컬 서명 키 파일은 생성했으며 원격 등록 완료로 간주하지 않는다.
